# 0.2.8 无线稳定性修复 / Wireless resilience

> 历史版本记录 / Historical version record. 当前候选版见 [0.2.10](Token与无线修复0.2.10.md)。

2026-10-25，基于本地提交 eeff298（固件原为 0.2.7）。

## 中文

旧日志有多次重新握手以及请求体未读完就断开的记录，但缺少断线时刻与原因，不能据此断定每次短暂离线的唯一原因。当前执行环境无法解析 GitHub 域名，未独立核实远端 HEAD。

已修复代码中的以下问题：

- TLS 握手在接收连接的线程执行，半开连接可能挡住设备的重连。现在在独立工作线程握手，握手限时 3 秒，空闲连接及请求体读取限时 10 秒。
- 固件对同一消息无限重试，可能拖住更新的心跳和按键消息。现在每条消息最多尝试两次；Wi-Fi 断开与 Bridge 状态分开，并在链路重新建立后关闭旧 TLS 连接。
- 中文快照使用 Unicode 转义增加传输长度。现在用 UTF-8；超过设备缓冲区时只尝试省去事件历史，完整保留审批字段。仍超限则明确报错，不能截断授权范围。
- 新增不含凭据或操作正文的诊断：Wi-Fi 断开次数及原因、HTTP 失败次数及阶段、恢复间隔和设备是否重启。阶段 1=连接/请求头，2=请求体写入，3=响应头，4=响应体/链路变化。

保持原有五秒失联保护及审批有效期检查。短暂网络故障仍可能表现为离线；本修复不延长可授权时间，也不声称能阻止 Mac 休眠或路由器断网。

验证：固件 0.2.8 使用 ESP-IDF 5.5.3 构建成功（2,355,776 字节）；六项新增单元测试通过。完整 Python 测试运行 156 项，143 项通过，13 项由于当前沙箱禁止 TCP/Unix socket 操作而中断，没有断言失败。控制器、音序及八组音频线程检查通过。真实 TLS 重连测试及更新后的设备稳定性尚待普通 Terminal / 实机验收。

更新：保持从实体审批入口启动的 App 和当前聊天打开，只在旧 Bridge 窗口 Control+C。连接 USB 数据线，运行项目中的「更新无线稳定性固件.command」。它先运行完整主机测试；通过后双读完整备份，只更新 factory 应用并回读校验，保留配网与 NVS，再启动更新后的 Bridge。不要用 ESP-IDF 构建输出的通用 flash 命令覆盖分区表或 bootloader。

## English

The local baseline is commit eeff298 / firmware 0.2.7. Existing logs show repeated handshakes and an incomplete request body, but lack enough timing/reason data to identify a single cause for every dropout. GitHub HEAD could not be independently checked because network DNS is unavailable in this execution environment.

The fix moves TLS handshakes from the accept loop into bounded workers; limits firmware retries per frame; discards old TLS connections after Wi-Fi link changes; encodes snapshots as UTF-8; and adds credential-free reconnect diagnostics. Oversized snapshots can omit history, but approval details are never truncated. Existing five-second approval freshness and expiry checks remain unchanged.

Firmware 0.2.8 built with ESP-IDF 5.5.3 (2,355,776 bytes). Six new unit checks passed. The full Python run had 143 passes and 13 socket-permission errors out of 156, with no assertion failures. Controller, tone and eight audio-worker checks passed. Real TLS reconnection and device endurance still require validation outside the sandbox.

Keep the adapted desktop App open, stop the old Bridge with Control+C, connect USB and run 更新无线稳定性固件.command. It runs the complete host tests before flashing, verifies two full backups, writes/verifies only the factory application and retains pairing/NVS, then starts the updated Bridge. The source changes are local; no new GitHub publication or device flash has been performed by this repair session.
