# 长请求实体审批 / Paged hardware approval

## 中文

V0.2.4 固件增加请求详情翻阅。它与桌面 App 当前聊天的原生审批转发配合使用，不通过新 CLI 聊天替代原 App。已确认设备刷入并校验成功，在线声明分页协议 1；用户已确认可以翻到末尾选择允许／拒绝，新字库不再显示方框。此前用户在 Mac 点了允许的申请不计为设备批准成功。

- 请求详情：短按上／下翻阅；长按下键前进一页，长按上键从头查看。确认键只静音。
- 详情全部翻到末尾后，再显示独立的决策页。没有默认选择。短按上键选允许，下键选拒绝。
- 短按并松开确认进入二次确认；再次长按确认约 1 秒提交。
- 决策页长按上键返回第一张详情页，清除选择；不能从详情页直接批准。
- 等待用户回复的提醒也支持翻阅，末尾只能确认已读，不能代替 Mac 上的回答。

Bridge 按固定字形宽度和行数换行，不调用模型、不删减申请原因、路径、命令或权限。未知字形及不可见控制字符显示为 Unicode 转义。每次只向硬件发送一页；完整原始请求只保留在 Mac 内存，摘要始终绑定原始请求。不能用摘要代替授权范围。

### 中文说明页

`0.2.4-app-relay-preview-human1` 修复初版直接显示 JSON 导致的十页英文和纯括号页。常见请求按中文模板显示申请联网、读取／写入路径、申请原因、工作目录、有效期。路径、命令和原因全文保留，不调用模型提炼。会话／请求路由 ID、内部时间戳在后台校验，不占显示页；命令的派生解析及没有选择的长期放行建议不代替原始命令。未识别的新参数仍逐项显示，避免遗漏额外范围。原请求摘要和原生授权回传完全不变。

这个修复只更新 Mac Bridge。保持 App 打开，在旧 Bridge 终端 Control+C，再运行 `仅启动桌面App桥接.command`。无需重新刷机、插 USB 或配网。129 项主机检查通过，使用真实 LVGL 字库渲染了中文说明。用户已重启加载，真实 App 的目录请求已分别通过设备允许／拒绝验收。状态接口新增 `last_device_decision`，只记录已匹配的设备选择，不包含路径、命令或账户信息，以区分 Mac 作答和硬件作答。

设备声明 `review_protocol: 1` 后才启用长内容批准。0.2.3 继续使用原来的一屏保护，不会在截断内容后突然开放批准。新的页请求和最后决策都校验 boot、Bridge epoch、请求 ID 和摘要；不能跳过未送达的页面、重复提交或在断线／过期后批准。

原生 App 审批的 Bridge 审阅期限为开始后最多 10 分钟，不会用翻页延长。若 App 自行取消、在 Mac 上作答或结束请求，则立即撤销。已有 App relay 的短读超时由兼容 JSON 空白保活解决，无需为此退出 App。官方同步 Hook 仍受其原有约 110 秒限制。

**长内容本身不再导致只许在 Mac 审批。** 已支持完整的网络／目录权限请求与含完整命令的执行请求。若原生回调未提供文件修改 diff，或出现尚未理解的额外授权语义，仍需在 Mac 审阅；不能把缺失的内容伪装成完整显示。

### 更新与验收

只在旧 Bridge 启动终端按 Control+C，保持 App 和当前聊天打开。连接 USB 后运行 `更新长请求审批固件.command`。脚本双读 8 MB 备份，只写 factory 应用；保留配网、NVS、bootloader 和分区表。完成后直接重新接入已经打开的 App relay，不自动发任务或批准请求。

主机测试覆盖长路径、多目录、完整命令、不可见字符、异步翻页、禁止跳页、返回首屏清除选择、二次确认、绑定错误、重启失效、准确原生回传及旧 relay 保活。LVGL 使用实际字库渲染了详情页和决策页。固件已为 ESP32-C3 构建并实际刷入；用户确认了物理分页与字库。App 真实目录请求已分别批准和拒绝，结果见 `桌面App实体审批验收.md`。其他审批类型仍按各自验证范围处理。

## English

V0.2.4 adds paged review to the existing desktop App's native approval relay. It does not replace the current chat with a new CLI chat. Flash verification and the capability handshake are confirmed. The user has verified pagination, final-page choices, and corrected Chinese glyphs. Real directory write permission requests have now passed both physical Allow and Deny, with matching device decisions and official tool results. Earlier requests allowed on Mac were excluded from hardware acceptance.

During review, Up/Down change detail pages; holding Up returns to the beginning. OK only silences reminders. A separate decision page appears after the last detail page. Short Up selects Allow, short Down selects Deny, short OK opens confirmation, and a fresh one-second OK hold submits. Holding Up clears the selection and returns to the first detail page. Nothing is preselected.

Wrapping is deterministic and uses no model summarization. Paths, commands, reasons, and permission scopes are retained. Unsupported/invisible characters are escaped visibly. Only one bounded page is sent to the device; the original request stays in Mac memory and remains bound to its digest. Firmware advertises the pagination capability explicitly; older firmware retains its existing single-screen restriction.

The `human1` Bridge revision replaces raw JSON with Chinese descriptions of network access, every read/write path, reason, working directory, and validity. Opaque routing IDs/timestamps stay in backend validation. Unselected persistent-policy suggestions and redundant command parsing do not replace the exact command. New unknown parameters remain visible. The original request digest and response permissions are unchanged. This is a Mac-only update: stop the old Bridge with Control+C and run `仅启动桌面App桥接.command`, keeping the App open. No firmware flash or USB connection is required. The status endpoint records bound physical decisions without logging request contents, so a Mac answer cannot be mistaken for a device answer.

Every navigation/decision is bound to the device boot, Bridge epoch, request ID, digest, and page. Unsent pages cannot be skipped. Disconnection, expiration, or an App-side resolution invalidates the request. Native reviews have a fixed ten-minute maximum; paging never extends it. Backward-compatible JSON whitespace keeps already-running relay readers alive. Synchronous Hooks retain their shorter timeout.

Length alone no longer disables hardware approval for complete native network/directory requests and commands. Missing file diffs and unimplemented extra-grant semantics still require Mac review. Read acknowledgements for user questions never grant permissions or answer the question.

Stop only the previous Bridge terminal with Control+C; keep the App/chat open. Connect USB and run `更新长请求审批固件.command`. The updater verifies two full backups and writes only the factory application, retaining pairing and other flash regions. Host/protocol/controller tests and actual-font LVGL previews are validated. Physical pagination, corrected glyphs, and real desktop App directory Allow/Deny are confirmed. These results do not automatically validate other approval types, App builds, or third-party gateways.
