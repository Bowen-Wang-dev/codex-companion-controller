# Token 与计费模型

## 不重叠的显示行
- 未缓存输入 = API 输入总数 − 缓存读取 − 缓存写入。
- 缓存读取、缓存写入分别列行和费率。
- 输出（非推理） = API 输出总数 − 推理。
- 推理单独列行；OpenAI 规则下使用输出单价。它已经在 API 输出总数中，合计只加一次。
- 展示总数是上述五行之和；不要再把缓存或推理加回 API 总数一次。

API 没有提供细分时必须明确未知；目前 provider CSV 没有 reasoning，旧适配将其设为 0，这是待改的来源完整性边界，而不是保证没有推理。

## 两种费率方式
配置文件：`controller/private/token_rates.json`，按精确模型 ID 匹配。
- custom：自定义基准价 × multiplier；旧文件没有倍率按 1，保留既有折后值，不能再自动乘 0.18。
- openai：内置已核对的 OpenAI 单价 × multiplier；默认倍率 1，不能把相近模型的价套到当前模型。
- 当前代码内置 gpt-6.1-sol；其他模型用 custom 或未来经核对新增。价格是当时快照，不是永久固定事实。不要把网关声称的“官方价”当独立验证。

当前 Sol 卡（USD / 百万 Token）：普通 输入2、缓存读0.1、缓存写2.5、输出10；长档 输入4、缓存读0.2、缓存写5、输出15。缓存写入卡为公开短 TTL 基准，当前计量缺少 TTL 细分，不能保证覆盖长期缓存收费。

长档条件：单次请求输入（含缓存）严格大于 272000。整笔请求套对应档，包括输出；不是超出部分阶梯计价，不按单次输出、整轮总量、全天累计或上下文容量判档。每笔判档后再汇总，普通档输出/推理同价，长档也同价。

## 统计来源与持久化
- 普通 App Server 数值事件与本机完成记录有不同累计历史，不可直接相加。
- ledger 保存线程/轮次/模型、原始累计基线及逐响应 ID/边界；重放/恢复/重连必须去重。
- compaction 调用可能漏在普通事件外，本机完成数值记录增量补入。
- provider CSV/TSV 只在能唯一归属已知轮次时补充缺失请求；迟到本机记录移除其 supplement。
- 清零只清本机累计，保留原始重放基线，不改变服务商账单、聊天或账号。
- 缺请求边界时不能拿累计总数猜一笔长上下文；大额旧历史估价可为未知。
- CSV 的 Input Tokens 是非缓存输入，与 Responses 的 input_tokens（含缓存）不同；Billed Cost 已乘倍率，不再折扣。

## 先前实际对账结论
曾用用户私有导出逐笔核对：普通与长档混合时单档估价会偏低；逐笔双档后与账单仅有逐笔舍入差异。真实行、IP、API Key 标签与总额未放入交接公开文档。
