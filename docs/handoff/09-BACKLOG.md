## 数据与工程改进

- provider CSV 没有 reasoning 字段时现有适配填 0；需设计来源完整性标记，避免将其解释为实际没有推理。
- 缓存写 TTL 与分档明细覆盖不足；内置价是快照。更新前核对来源和费率约定，不覆盖自定义价。
- 4096 字节 snapshot 上限可能限制较大计量明细；保持授权内容完整，后续评估按页传输的紧凑协议。
- 评估账本持久化体积、逐请求估价扫描成本、relay 长期会话集合增长及后台文件生命周期；需测量后再决定缓存或模块拆分。
- 固件网络初始化失败后的资源清理、任务创建失败路径等需结合 SDK 构建及故障注入完善；本次没有为未经验证的优化修改硬件驱动。
- `service.py` 同时承担状态、审批、计量和服务生命周期职责。可在行为测试保护下逐步拆分；本次仅抽取共享 App 探测及用量完整性检查，不进行整体重写。
