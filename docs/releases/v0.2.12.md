## 本版变化

- 使用当前 ChatGPT/Codex 桌面 App 原聊天的原生审批卡片，与 AI Passport 同时显示同一请求。保留原 App、账户和聊天，不新建会话、不使用独立 Companion/Tk 审批窗口。
- 桌面模式的 PermissionRequest 与权限 PreToolUse Hook 返回空结果，避免抢先阻塞原生卡片。空结果不是自动批准；之后的真实 native 请求由现有 stdio relay 同步到设备。
- 同一审批由 App 或设备先答者生效，另一端结束；设备批准仍需末页选择、二次确认和匹配的实际提交回执。
- 设备详情页长按确认发送绑定当前请求的 Mac 交接，激活已运行且精确版本/摘要校验通过的原 App，不自动点击审批按钮。
- 修复普通 Mac Terminal 缺少裸 `python` 时更新中止：显式区分 Bridge 与刷写解释器，停 Bridge 前检查 esptool 4.x。
- Bridge 诊断修订号为 `0.2.12-native-app`，`approval_ui=native_app`；设备固件为 `0.2.12`。旧独立窗口入口只保留为无操作兼容文件，不能恢复该方案。

## 五项真实设备验收

组合：本机登记的 App **26.1027.30824**、设备固件 **0.2.12**、原 App 聊天及原生 relay。用户逐项按要求操作，每项反馈 passed，最后确认第 5 项通过。

| 项目 | 人工操作 | 实际结果与证据 |
|---|---|---|
| 1 | 只在设备允许，Mac 不操作 | 只读命令执行；Broker 记录 source=desktop、choice=allow，匹配的 delivery stage=submitted；用户确认 😆 和 Mac 卡片结束 |
| 2 | 只在设备拒绝，Mac 不操作 | 工具返回 rejected by user，命令未执行；用户确认设备直接 😭，Mac 卡片结束 |
| 3 | 设备不操作，只在 Mac 原生卡片允许 | 只读命令打印 TEST_3_NATIVE_MAC_ALLOW 成功标记；用户确认设备待审批页面结束 |
| 4 | 设备不操作，只在 Mac 原生卡片拒绝 | 工具返回 rejected by user，命令未执行；用户确认设备待审批页面结束 |
| 5 | 从其他窗口在设备详情长按确认转到 Mac，再在 Mac 允许 | 只读命令打印 TEST_5_DEVICE_HANDOFF_NATIVE_MAC_ALLOW 成功标记；用户确认唤回原 App、交接没有自动批准、随后设备待审批页面结束 |

这是真实 App/设备人工测试，不是 mock；第 2/4 项拒绝是预期结果。仅第 1 项捕获了独立的 native 提交回执，不声称每项均采集了回执。完整上下文与本机证据留在私有验收记录，不公开会话 ID 或运行身份。

## 升级方式

日常仍只使用 `controller/Codex Companion 控制台.command`：

```bash
bash "/你的工程路径/controller/Codex Companion 控制台.command"
```

- **设备已经是 0.2.12**：保留 App 与原聊天，选主菜单 **2 → 子菜单 2「安全重启 Bridge」**，保持终端运行。无待审批时才能重启；无需再次刷机或重新配网。
- **设备仍为旧固件**：先在本机准备并校验 0.2.12 镜像，用 USB 数据线连接，选菜单 **7**。入口会先测试、检查 App/镜像/刷写解释器，确认后停 Bridge、双读备份并校验 live 分区，仅写 factory 应用并回读验证，再启动 Bridge 接回 App。
- 普通 Terminal 无 IDF 环境时，在本机 ignored `controller/private/local-env.sh` 明确配置 `CONTROLLER_FLASH_PYTHON` 为已有、可导入 esptool 4.x 的 Python 绝对路径。Bridge 继续使用 `CONTROLLER_BRIDGE_PYTHON`，不能混为同一环境的保证。
- GitHub 源码包不含 Apple 图像/含图镜像或本机恢复依赖，不能当作拿到即刷的完整设备恢复包。禁止使用 IDF 输出的通用 flash 命令或整片擦除。

## 验证边界

- 发布前重新运行的主机检查以本次发布记录为准；历史各轮测试数量不相加。
- App 启动/焦点适配仍按精确版本和文件摘要校验，未知升级拒绝套用；内部启动开关不是稳定公开设置。
- 文件 diff 缺失、未知额外授权、其他权限种类、休眠唤醒、长时间稳定性、所有项目/客户端未因这五项测试而自动验收。
- 原生协议转发不等于 UI 已绘制回执。0.2.12 的设备交接页仍可能保守显示“正在请求 Mac 显示／尚未收到窗口显示回执”，不能把它误当作新的交接失败或伪造已显示状态；本次以人工确认原 App 被唤回为验收依据。
