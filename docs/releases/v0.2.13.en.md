- Entries: update launch / maintenance prompts, versions and manifest checks for consistent build / safe update. Use existing console, no new top-level command in that version.
- Regression / build: replace old handoff cases; cover harmless details hold / release, confirmation submission, old-message isolation, dual Allow / Deny and opposite-side clearing. Check Chinese glyphs, relevant Python / C and ESP-IDF build. Record actual execution without treating mocks, builds or image checks as hardware acceptance.

Removing unused code simplifies paths; no resource measurement was performed and no quantified compute, memory or power improvement is claimed. Reuse existing modules without wholesale rewrites or backlog expansion.

## Deployment and verification boundaries

The original stage completed source / regressions / build without App / Bridge restart or flash. Later device versions are accounted for above, so “never deployed” is no longer a present fact. The code review did not restart services, flash, change pairing / accounts / counters or release a version. Host checks are not hardware acceptance. Firmware updates still use menu 7 dual backups, live partition checks and application-only writes, never whole erase. Apple assets, artwork firmware and private data remain unpublished.

Later complete original-chat cases should cover device / original-App Allow / Deny, opposite-side clearing, computer-details prompt, harmless details hold / release and second-confirmation hold-submit. Other permission types / stability remain independently unverified. Old devices retain handoff until updated, but new Bridge ignores that message; do not keep using it.
