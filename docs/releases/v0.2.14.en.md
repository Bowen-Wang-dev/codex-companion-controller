# v0.2.14: installation entry determines device language

[简体中文（默认）](v0.2.14.md) · English

Updated 2026-11-03 (Australia/Sydney). Firmware source `0.2.14`, Bridge `0.2.14-native-app`. This phase completes source and local Chinese / English builds without flashing for the user or restarting real services. Existing hardware feedback remains tied to prior versions. This is a version record, not a new Git tag or public artwork-containing firmware release.

## Usage rule

Build / install from English `Codex Companion Console.command` / `Codex Companion Console.cmd` and the device is English from startup, including offline / reboot. Chinese-entry installation is Chinese. Later choosing another PC console language does not change the installed device language. Windows / macOS menu 7 both offer build, validation and safe-update submenus; see the [device language guide](../handoff/13-DEVICE-LANGUAGES.en.md).

## Changes

- Firmware gains a compiled language and 126 static device messages covering startup / offline, six pages, pairing, approval review, second confirmation, metering / reset and audio prompts. Chinese remains default; original Apple emoji remain.
- New hello sends `ui_language_protocol=1` and `ui_language`; Bridge generates system titles, authorization descriptions, events, states and genuine receipts in device language. Old devices remain Chinese. Language changes within a boot are ignored so pending review does not switch languages.
- Translate only explicitly marked system text. Original commands, paths, reasons, questions and unknown field values remain unchanged. Complete pagination, original digest, Allow / Deny results, delivered-final-page checks, second confirmation and real submitted receipts remain.
- Installation entries pass the build option; manifest confirms `ui_language` from a unique compiled image marker. Entry / manifest / image disagreement rejects early without stopping Bridge or writing. Windows / macOS share language checks; Mac retains its safe updater.
- English labels use existing Montserrat; Chinese user content uses the original font. Adjusted title widths / receipts and repaired existing long-Chinese-receipt overlap. Preview tool reuses actual firmware `render()`, locked LVGL and real fonts with mocked hardware; output stays private.

- New hello uses a bounded 768-byte transmit buffer so language fields plus diagnostic counters fit beyond the former 512-byte limit. The maximum-frame regression passed; approval-detail receive capacity remains 4096 bytes. Forty offline Chinese / English LVGL screens have zero label overlap / out-of-bounds findings.

## Actual verification

- Full Windows Controller regression: 310 tests, OK (18 skipped), including new device-language / original-data / delivered-page protection and image-language cases. Phase-two host-language tests remain.
- Chinese / English compiled defaults, the same three-button navigation / approval / reset checks, tones and eight mocked BSP / RTOS audio groups passed. A pre-existing misleading-indentation warning in a test fixture was split into separate lines for Linux GCC; audio behavior did not change.
- Five isolated macOS maintenance-entry cases passed under WSL with fake interpreters; this is not native macOS or hardware flashing acceptance.
- ESP-IDF 5.5.3 built both artwork-containing variants. Source fingerprints / language / file digests passed; all seven original RGB565 arrays occur in both images. esptool 4.8.1 checksum / Validation Hash passed.

## Still unaccepted

No real serial port was opened, no flashing, pairing, reset, Hook registration, account change or real App / Bridge restart. Actual new-version screen layout, Chinese / English startup / reboot / offline behavior, pairing prompts, complete dual-side Allow / Deny, opposite-side clearing, all permission types and stability require installed-device testing. Native macOS execution was not performed this round.

Updating retains two full 8 MB backups, live partitions / identity checks, application-only writes and readback verification. No whole erase, bootloader / partition-table / existing-NVS write or automatic write retry. Phase-one docs `48603c8` and phase-two host interaction `cc1bbfd` remain separate history; this version does not resume other backlog.
